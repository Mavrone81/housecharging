# VAPT Report — MCTS Community Utility Billing

- **Target:** https://mcts.urbanwerkzsg.com (DigitalOcean droplet, region sgp1)
- **Date:** 2026-06-05
- **Type:** Authenticated grey-box web application + infrastructure assessment
- **Tester:** Claude (authorized by the system owner)
- **Methodology:** Manual testing of authentication, authorization, IDOR, injection,
  brute-force, transport/headers, error handling, business logic; source review for
  XSS/secret handling; host/infra inspection (ports, firewall, SSH, file perms,
  container privilege, dependency audit).

> Sensitive values (current admin password) are redacted in this document.

## Executive summary

The application core is **solid** — no SQL injection, working authentication/authorization,
no IDOR, no sensitive-data leakage, bcrypt hashing, verified JWT signatures, and zero known
dependency CVEs. **No Critical vulnerabilities were found in the app.**

The meaningful risk is in **operational hardening and the shared host**: no login
rate-limiting, a weak admin password on a public URL, missing security headers, the
container running as root, and — most importantly — many sibling services exposed to the
internet on the same firewall-less droplet that hosts the billing database.

| Severity | Count |
|---|---|
| Critical | 0 |
| High | 3 |
| Medium | 5 |
| Low | 7 |
| Passed / positive | 13 |

## High

### H-1 — No rate limiting / brute-force protection on login
12 rapid invalid admin logins all returned `401` with no throttling, lockout, or `429`.
Combined with H-2, the admin account is brute-forceable.
- **Evidence:** 12× POST `/api/auth/admin/login` with wrong passwords → `401 ×12`.
- **Remediation:** add `express-rate-limit` (e.g. 5–10/min/IP) on `/api/auth/*`; consider
  account lockout/backoff after repeated failures.

### H-2 — Weak admin password on a public endpoint
The admin password is short and predictable, with no rate limit in front of it.
- **Remediation:** set a long random password and/or enforce a strong-password policy.

### H-3 — Shared host is wide open (no firewall + many public services)
The droplet has `ufw` inactive and iptables `INPUT` policy `ACCEPT`. Ports bound to
`0.0.0.0`: `22, 80, 443, 3000, 3002, 4000-4013, 4998`. The 3000 / 4000-series / 4998
services are other applications (HRMS, urbanwerkz, vorkhive) on the **same machine as the
MCTS database**. Compromise of any one is a pivot to the billing data.
- **Remediation:** DigitalOcean Cloud Firewall (default-deny inbound; allow only 80/443 +
  trusted SSH source). Bind internal services to localhost where possible.

## Medium

### M-1 — Missing security headers
No `Strict-Transport-Security` (HSTS), `Content-Security-Policy`, `X-Frame-Options`,
`X-Content-Type-Options`, `Referrer-Policy`, or `Permissions-Policy`. No HSTS → SSL-strip
risk; no CSP → larger XSS blast radius.
- **Remediation:** HSTS in nginx; `helmet` (or equivalent headers) in Express, including a CSP.

### M-2 — Container runs as root
App process is `uid=0(root)` inside the container; an app RCE would be root.
- **Remediation:** add `USER node` to the Dockerfile; run with `no-new-privileges`.

### M-3 — No encryption at rest
Plain ext4 root volume, no LUKS/dm-crypt; Postgres data unencrypted on disk.
- **Status:** in progress — DigitalOcean Block Storage (DO-encrypted) migration chosen,
  pending volume attach.

### M-4 — Backups are local-only
Nightly dumps are stored on the same disk as the database; disk loss loses both.
- **Remediation:** ship dumps off-box (object storage) and encrypt the dump files.
- **Status:** tooling shipped — `ops/mcts-db-offsite.sh` encrypts each dump with `age`
  (public-key) and uploads to S3-compatible storage. Pending: configure
  `/etc/mcts-offsite.env` and the cron entry on the droplet (see `ops/README.md`).

### M-5 — SSH allows root login / ambiguous password-auth config
`PermitRootLogin yes`; `PasswordAuthentication` is declared in two places (`yes` then `no`).
`fail2ban` is active (good).
- **Remediation:** confirm `PasswordAuthentication no` is effective; set
  `PermitRootLogin prohibit-password` (or `no`).

## Low

- **L-1 — Weak/no password policy:** a 1-character password was accepted at registration
  (`201`). Enforce a minimum length (e.g. ≥8) on register, admin-create, and reset.
- **L-2 — Username enumeration:** registration returns `409` for an existing username.
  (Login itself is safe — generic error message.)
- **L-3 — Technology fingerprinting:** `X-Powered-By: Express` and
  `Server: nginx/1.24.0 (Ubuntu)` disclosed. Fix: `app.disable('x-powered-by')` and nginx
  `server_tokens off`.
- **L-4 — JWT design:** 12h tokens, no revocation/refresh, stored in `localStorage`.
  Acceptable for a pilot; XSS could exfiltrate a token (CSP in M-1 mitigates).
- **L-5 — Registration accepts non-existent house numbers** (`201`). Mitigated by the admin
  approval gate and the "no matching house" UI flag.
- **L-6 — Error handler returns `err.message`** for any error. Fine for 4xx; return a
  generic message for 5xx to avoid leaking internal detail. **Fixed** in `app.js`
  (generic "Server error" for `status >= 500`, specific messages kept for 4xx).
- **L-7 — JWT secret hard-coded fallback** (`dev-insecure-secret-change-me`) if the env var
  is unset — fail-open. Make it fail-closed (refuse to boot without `JWT_SECRET`).

## Passed / positive findings

- SQL injection: parameterized queries; `' OR '1'='1` and `'; DROP TABLE owners;--` both
  returned `401`, tables intact.
- Authorization separation: owner→admin endpoints `403`; admin→owner endpoint `403`.
- IDOR: owner fetching another house's payment proof returned `404`.
- JWT signature enforced: `alg=none` and old-secret forgery both `401`.
- No `password_hash` in any API response.
- JWT payload carries no secrets.
- `npm audit`: 0 vulnerabilities.
- Postgres not internet-reachable (public-IP `:5432` connection refused; private bridge only).
- TLS 1.2 enforced (TLS 1.0 refused); valid Let's Encrypt certificate.
- `.env` is `600`/root and excluded from the Docker image (`.dockerignore`).
- Backups directory is `700`.
- `fail2ban` active.
- Output encoding: `esc()` used for user-controlled fields (community name, address,
  username, house/owner names); safe custom formula evaluator (no `eval`/`Function`).

## Recommendations

### Application (code/config changes in this repo)
1. **Rate-limit auth endpoints (H-1).** Add `express-rate-limit` to `/api/auth/*`
   (e.g. 10 requests/min/IP, with a stricter 5/15min on repeated failures). Return `429`.
2. **Rotate the admin password (H-2)** to a long random value and enforce a
   **minimum password length ≥ 8 (L-1)** in `auth.js` register + `admin.js` create/reset.
3. **Add security headers (M-1)** via `helmet` in `app.js`: HSTS, `X-Content-Type-Options`,
   `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Permissions-Policy`, and a
   **Content-Security-Policy** (`default-src 'self'`; allow the Google Fonts origins used by
   the client; `img-src 'self' data:` for logo/QR/proof data URLs).
4. **Hide framework fingerprints (L-3):** `app.disable('x-powered-by')` and nginx
   `server_tokens off;`.
5. **Fail closed on missing secret (L-7):** in `auth.js`, throw on startup if `JWT_SECRET`
   is unset instead of using the dev fallback.
6. **Generic 5xx errors (L-6):** in the error handler, return a generic message for
   `status >= 500` (keep specific messages for 4xx).
7. **Run the container as non-root (M-2):** add `USER node` to the Dockerfile and
   `security_opt: ["no-new-privileges:true"]` in docker-compose.
8. **Validate house on registration (L-5)** or keep the approval gate as the control
   (document it as the accepted mitigation).

### Infrastructure / host
9. **DigitalOcean Cloud Firewall (H-3)** — default-deny inbound; allow only:
   `TCP 80, 443` from anywhere; `TCP 22` from your admin IP(s) only. Audit the
   `3000/3002/4000-4013/4998` services and restrict or bind them to localhost.
10. **SSH hardening (M-5):** confirm `PasswordAuthentication no`; set
    `PermitRootLogin prohibit-password`; keep `fail2ban`.
11. **Encryption at rest (M-3):** complete the DO Block Storage (DO-encrypted) volume
    migration for the Postgres data directory.
12. **Off-box, encrypted backups (M-4):** push the nightly dump to object storage
    (e.g. DO Spaces/S3) and encrypt the dump (age/gpg) before upload.

### Operational / ongoing
13. Periodic `npm audit` and base-image patching; keep nginx updated.
14. Add minimal request logging/alerting for repeated `401`s (early brute-force signal).
15. Re-test after remediation (re-run this VAPT battery) and before loading real data at scale.
